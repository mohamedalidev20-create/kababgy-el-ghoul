# كبابجي الغول — موقع المطعم

## الملفات
- `index.html`: صفحات الموقع والواجهة.
- `style.css`: التصميم المتجاوب.
- `app.js`: المنيو والسلة والطلبات ولوحة الإدارة.
- `firebase-config.js`: بيانات ربط Firebase.
- `firestore.rules`: قواعد أمان قاعدة البيانات.

## تشغيل سريع
1. ارفع الملفات كلها إلى مستودع GitHub واحد.
2. من إعدادات المستودع فعّل GitHub Pages من الفرع `main` والمجلد `/root`.
3. افتح `firebase-config.js` وضع بيانات مشروع Firebase الحقيقية.
4. من Firebase Console أنشئ Firestore Database.
5. من Authentication فعّل Email/Password وأنشئ حساباً للإدارة بنفسك. لا تضف زر تسجيل حساب داخل الموقع ولا تفعّل التسجيل العام.
6. انشر محتوى `firestore.rules` في Firestore Rules.
7. افتح رابط الموقع. لوحة الإدارة من خلال إضافة `#admin` إلى الرابط، مثال: `https://username.github.io/repository/#admin`.

## مهم جداً قبل الاستخدام الحقيقي
- الأسعار والأصناف في `app.js` أمثلة مبدئية مستخلصة بقدر الإمكان من صور المنيو، ويجب مراجعتها مع المطعم قبل النشر.
- أرقام الهاتف والعنوان مأخوذة من الصور وقد تحتاج تأكيداً. العنوان التفصيلي وساعات العمل ورسوم التوصيل غير مؤكدة.
- صور الطعام الحالية صور توضيحية من Unsplash وليست صور المطعم. استبدلها بصور أصلية للأطباق.
- بدون إعداد Firebase سيعمل الموقع في وضع تجريبي محلي: الطلبات تحفظ على نفس الجهاز فقط ولا تصل للمطعم.
- بعد إعداد Firebase، الطلبات تصل إلى Firestore وتظهر في لوحة الإدارة. رابط الإدارة ليس حماية بحد ذاته؛ الحماية الفعلية عبر تسجيل الدخول وقواعد Firestore.
- أنشئ حساب إدارة موثوقاً من Firebase Console، ولا تشارك كلمة المرور.
- قواعد Firestore الحالية تسمح لأي مستخدم مسجل الدخول بقراءة/تعديل الطلبات؛ لذلك لا تنشئ حسابات عامة. لمستوى إنتاج أعلى، استخدم Firebase custom claims لدور admin، وتحقق من صحة الأسعار على الخادم عبر Cloud Functions قبل اعتماد الطلب.
- الموقع لا يخصم أموالاً إلكترونياً ولا يتصل بشركة توصيل؛ طريقة الدفع الحالية عند الاستلام مع تأكيد المطعم للطلب.
- اختبر الطلبات من هاتف زبون ومن حساب الإدارة قبل نشر الموقع للعملاء.

## تعديل المنيو
افتح `app.js` وعدّل عناصر مصفوفة `menu`. كل عنصر يحتوي على:
`id`, `name`, `category`, `price`, `desc`, `img`.
